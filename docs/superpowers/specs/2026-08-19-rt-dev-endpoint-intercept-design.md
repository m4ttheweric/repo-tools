# rt dev-endpoint service + generic command interception — design

**Ticket:** RT-28 (requirements + AC live on the ticket; this doc adds the concrete shapes)
**Date:** 2026-08-19
**Status:** Approved design, pre-implementation

## Problem

`@acme/dev-ports` solves per-worktree dev-server ports and env injection for exactly one repo, with policy and mechanism welded together in a 576-line PATH shim. rt harvests the mechanism: the daemon owns port allocation and endpoint discovery, and rt owns a generic command-interception capability so the just-works invariant survives (you type `pnpm start` where you always type it; nobody asks rt anything). The pack keeps only domain hooks.

## Decisions and rationale

1. **Per-repo config, two new read-only keys** in `~/.mattstack/rt/repos/<repo>/config.json`, following the `worktrees` key precedent (`lib/worktree/config.ts`): a new module reads only its keys, never writes, never touches `lib/repo-config.ts` (whose save path drops unknown keys).

```jsonc
{
  "roles": {
    "backend": {
      "pool": [{ "from": 10400, "to": 10463 }],        // allocating role
      "preserveEnv": ["POSTGRES_URL", "FEATURE_FLAG_*"],
      "env": { "PORT": "${port}" }
    },
    "portal": {
      "pool": [4001, 5001, 6001, 7001, 8001, 9001],     // constrained pool IS the constraint
      "needs": ["backend"],
      "env": {
        "PORT": "${port}",
        "REACT_APP_ENDPOINT": "http://localhost:${roles.backend.port}"
      },
      "hook": "bun /path/to/pack/portal-hook.ts"      // domain side effects, pack-owned
    },
    "frontend": { "fixedPort": 4002, "needs": ["backend"], "env": { "REACT_APP_ENDPOINT": "http://localhost:${roles.backend.port}" } }
  },
  "intercepts": [
    {
      "command": "doppler",
      "matches": [
        { "cwdGlob": "apps/backend{,/**}", "argPattern": "src/app/server|process\\.env\\.PORT", "role": "backend",
          "argInject": { "afterArg": "run", "template": "--preserve-env=${envKeys}", "skipIfArgPresent": "--preserve-env" } },
        { "cwdGlob": "apps/portal{,/**}", "argPattern": "parcel", "role": "portal",
          "argInject": { "afterArg": "run", "template": "--preserve-env=${envKeys}", "skipIfArgPresent": "--preserve-env" } }
      ]
    }
  ]
}
```

Domain names (`REACT_APP_ENDPOINT`, Auth0 pool values, doppler's flag) appear only as config VALUES in the user overlay; rt code never contains them. Interceptor declarations come only from this overlay, never from repo-committed files (a cloned repo must not rewrite what commands do).

2. **Allocation lives in the daemon.** Claims are per repo in `~/.mattstack/rt/repos/<repo>/endpoints.json`, atomic `writeJson`, guarded by the registry-style epoch counter (claim is a load→await→save flow on a shared event loop). Lowest-available from the role's pool; sticky per worktree for the worktree's life; `worktree:disposed` (daemon broadcast composite, extended with a third fan-out beside `cron.onBroadcast`) releases claims promptly; probe-based pruning of OTHER worktrees' dead claims stays as the crash backstop. Bind-probe before honoring anything (DECK-9). The verbatim dev-ports liveness lessons hold: pid is liveness never age, boot-window claims are live while their start pid answers, self-claims survive restarts, no TTLs.

3. **Interception = a 3-line sh shim that execs `rt intercept run`.** rt materializes `~/.local/bin/<command>` (never `rt` itself, that name is dev-mode's) plus a generated rules file `~/.mattstack/rt/intercepts.json` (from the repo index + each repo's overlay, regenerated by `rt intercept install` and on daemon config watch). `rt intercept run <command> -- <args...>`:
   - no rules for the command, or `RT_INTERCEPT_BYPASS=1` → exec the real binary immediately (real = PATH scan skipping the shim path; `RT_INTERCEPT_REAL` overrides for tests). No daemon contact.
   - rules exist → one `git rev-parse --show-toplevel` + remote-URL check against the declaring repo, cwdGlob (toplevel-relative) + argPattern match; no match → exec real.
   - match → `daemonQuery("endpoint:claim", ...)`; daemon null or error → stderr notice, exec real untouched (fail open; interception never blocks a start).
   - claim ok → render env templates, collect preserveEnv keys present in the caller env, apply argInject, run the role hook if declared (JSON in/out, fail-open), then spawn the real binary inherit-stdio with signal forwarding and await it (today's passthrough shape; the rt process pid is the boot-window liveness signal recorded in the claim).
   The daemon never spawns dev servers (managed-process deprecation stands).

4. **Consumers** get `endpoint:lookup` (and `rt endpoint lookup <role>`): `{ port, url, running, claimed }` plus, when down, the role's start context — the URL-or-exact-command answer. `stage-evidence`'s generic fallback consumes this later. `/api/ports` stays observational and untouched.

5. **Honest magic:** `rt intercept status` (declared intercepts, shim installed/current, last-hit provenance), `RT_INTERCEPT_DEBUG=1` stderr trace, and an `rt verify` check (shim missing/stale for a declared intercept = warn; probe fn lives in the owning module).

6. **Out of scope here (follow-up in acme-tools):** the acme pack adapter — its hook script (config.js write, token-capture NODE_OPTIONS), the overlay config values, migration from `~/.acme/dev-ports.state.json`, and retiring the old `~/.local/bin/doppler` shim. rt ships generic and proves itself in e2e with a synthetic repo.

## Command surface

Daemon (HandlerMap, not rt-client-cataloged in v1): `endpoint:claim {repo, worktree, role, pid?}`, `endpoint:lookup {repo, worktree, role}`, `endpoint:release {repo, worktree, role?}`, `endpoint:status {repo?}`. CLI: `rt intercept status|install|uninstall` + hidden `run`; `rt endpoint lookup <role>`.
